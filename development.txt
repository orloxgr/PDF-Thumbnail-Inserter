## PHP architecture

`pdf-thumbnail-inserter.php` contains the plugin header, direct-access guard, root path constants and bootstrap. `includes/class-plugin.php` preserves `PDF_Thumbnail_Inserter::instance()`, its public methods/constants and the ordered WordPress callbacks. It creates and wires the internal collaborators before registering hooks. Subsystems call their explicitly declared collaborators; no service locator, magic dispatch or external autoloader is used.

| Runtime file under includes/ | Responsibility |
| --- | --- |
| class-settings.php | Defaults, validation and legacy option migration |
| class-admin.php | Settings/media UI and environment status |
| class-assets.php | Conditional script/style registration and loading |
| class-translations.php | Language-pack and local catalogue loading |
| class-blocks.php | Gutenberg registration and rendering integration |
| class-media.php | Authenticated media/AJAX entry points and upload integration |
| class-file-resolver.php | Local file validation and attachment URL lookup |
| class-preview-storage.php | Locks, owned attachments, publication and deletion cleanup |
| class-preview-generation.php | Core/server preview generation and failure cleanup |
| class-previews.php | Available preview selection and fallbacks |
| class-maintenance.php | Resumable bounded maintenance batches |
| class-discovery.php | PDF discovery in stored content and blocks |
| class-reference-lookup.php | Legacy reference/title matching |
| class-cards.php | Shortcode/card rendering and attribute handling |
| class-viewer.php | Public viewer and document-cover resources |
| class-featured-images.php | Featured-image fallbacks and listing visuals |
| class-listing-filters.php | Archive/excerpt/content output integration |
| class-elementor.php | Optional Elementor dynamic tag and widget |
| class-runtime-state.php | Shared request-local caches, locks and render contexts |

The public facade remains the callback owner, including callbacks registered later by settings, block registration, output buffering and temporary metadata-hook removal. The internal components and their wiring methods are not extension APIs. This is an organizational refactor: option/meta names, persistent data, shortcode aliases and PHP 7.4 / WordPress 6.0 requirements are retained; no speed improvement is claimed.

`tests/architecture-regression.php` compares public signatures/defaults/constants and the ordered hook registrations against a contract captured from the published 2.01.01 ZIP. It also checks root paths, callable callbacks, no bootstrap output and repeated loading. `tests/component-access.php` lets existing behavior tests reach the owning component without exposing test helpers in the distributed plugin; it also supports the old monolithic release for upgrade tests.

`tests/wordpress-integration.php` installs the ZIP and checks real WordPress APIs on an explicitly disposable site. It requires `PTI_TEST_DISPOSABLE=true`; see its header for the install and verification phases. The test creates attachments and changes settings, so use a fresh test database.

`tests/readiness-wordpress.php` exercises actual settings, block rendering, preview publication/rollback, local-file failures and optional Imagick/Ghostscript conversion. Its header describes the explicit disposable-site constants; run it directly with PHP so frontend filters are exercised. The site must have environment type `local` and cron disabled. `tests/preview-lock-concurrency.php` and `tests/preview-discovery-queries.php` take the disposable WordPress root as a CLI argument and require the environment variable `PTI_TEST_DISPOSABLE=true`. These checks create and remove synthetic fixtures and must never run against a live site.

`tests/server-maintenance-wordpress.php` tests real resumable jobs, failures, concurrent deletion/new uploads, lock contention and bounded discovery on a disposable site with Imagick. `tests/server-maintenance-http.php` requires an owned loopback HTTP server with Imagick; it tests actual authenticated form/AJAX requests, CSRF and object permissions, multipart image saving/replay and media-model refresh. Both take the disposable WordPress root as their argument and require `PTI_TEST_DISPOSABLE=true`; fixtures and sessions are removed afterward.

`tests/deletion-concurrency.php` checks actual cross-process writer/deletion contention, ownership, third-party deletion vetoes and stale publication paths. `tests/upload-http.php` checks actual REST PDF uploads and conditional Media Add New assets with automatic previews on and off. Both require the same disposable-site root and environment variable; the HTTP test additionally needs its owned loopback server. `tests/viewer-regression.cjs` covers lazy page batches, viewport rendering, pixel bounds, cancellation and worker disposal using explicit browser/PDF mocks.

With the same disposable-site root and `PTI_TEST_DISPOSABLE=true`, `tests/reference-lookup-wordpress.php` checks cold/warm query budgets and filename cache invalidation; `tests/warnings-wordpress.php` verifies real excerpt hooks, routing isolation and literal SQL patterns. `tests/translations-wordpress.php` uses fresh processes and temporary MO fixtures to verify language-pack priority, local fallback, missing translations and repeated locale switching. It refuses to replace existing translation files. `tests/public-resources-http.php` requires the owned loopback server and checks actual anonymous viewer/cover responses, malformed inputs and absence of data mutations. The pinned PHPStan configuration and source-backed runtime contracts are in `tools/phpstan/`; they add no ignores or baseline and are excluded from the ZIP.

`tests/lifecycle-wordpress.php` must start on a **fresh disposable local site without this plugin or its options**. Set `PTI_TEST_DISPOSABLE=true`. Each phase is a separate PHP process: `php tests/lifecycle-wordpress.php /path/to/wp PHASE`. Run `init`, install/activate the ZIP with WordPress/WP-CLI, run `fresh` and `legacy`, deactivate the plugin, run `inactive`, uninstall through WordPress (including removal of its files), run `uninstalled`, reinstall/activate the ZIP, and run `reinstalled`. The synthetic PDF, child preview, settings and stored content are retained for an upgrade check. To establish an actual published starting version, install that release ZIP and run `baseline ZIP_PATH`; then install/activate the new version and run `upgraded VERSION` followed by `cleanup VERSION`. Never run these commands on production. An additional HTTP server or browser is not required for these native lifecycle checks.

`python scripts/verify_pdfjs.py` checks the pinned PDF.js npm artifact integrity, compares every bundled library/resource/notice against its documented upstream source and queries the npm advisory API for that exact version. It downloads public metadata/artifacts only; it does not upgrade runtime files. Corresponding source/build links and supplemental QuickJS notice provenance are recorded in `assets/pdfjs/VERSION.txt` and the **Source Code and Build Instructions** section below.

Build the installable ZIP with `python scripts/package.py`. The `pdf-thumbnail-inserter/` archive includes only `LICENSE`, `readme.txt`, `development.txt`, `changelog.txt`, the plugin PHP entrypoint and Git-tracked includes/assets/blocks. The script checks version consistency, archive integrity, its distribution manifest, every packaged byte against the source and that every runtime PHP include is staged. Output goes to `dist/`; README.md, tests, development scripts, audit evidence, directory artwork, agent skills, Git metadata and local archives are excluded. Stage new runtime files and the changelog before building.

Before publication, scan the exact extracted ZIP and a snapshot of tracked files with Gitleaks; use its Git mode for the repository history. Keep reports redacted and review any detected locations without publishing secret values. Separately inspect for private endpoints and deployment paths: a clean secret scan does not identify every kind of private infrastructure detail. Retain upstream license/source notices and verify any library-origin finding against the corresponding official distribution.

The [readiness audit](https://github.com/orloxgr/PDF-Thumbnail-Inserter/blob/main/docs/readiness-audit.md) records the complete requirement matrix, fixes, tool findings and verification limits.

## Source Code and Build Instructions

The plugin's source code, tests and release packaging script are publicly maintained at:
https://github.com/orloxgr/PDF-Thumbnail-Inserter

For the source corresponding to this release, use the v2.01.02 tag. The plugin's own PHP, JavaScript and CSS are distributed as readable source and need no compilation. From a checkout of that tag, run `python scripts/package.py` with Python 3 and Git available to create the installable ZIP in `dist/`.

The plugin bundles the official PDF.js 6.3.289 distribution under the Apache-2.0 license. Its minified module and worker retain their upstream contents; `build/pdf.min.mjs` and `build/pdf.worker.min.mjs` are named `pdf.min.js` and `pdf.worker.min.js` in this plugin.

* Corresponding readable PDF.js source: https://github.com/mozilla/pdf.js/tree/v6.3.289
* Upstream build instructions and tools: https://github.com/mozilla/pdf.js/blob/v6.3.289/README.md#building-pdfjs
* Official prebuilt distribution: https://www.npmjs.com/package/pdfjs-dist/v/6.3.289

Individual font, decoder and sandbox licenses are included with their files. The two QuickJS MIT notices omitted from the upstream 6.3.289 package are supplied verbatim from Mozilla's v6.5.438 source; this notice repair does not upgrade the runtime:
https://github.com/mozilla/pdf.js/tree/v6.5.438/external/quickjs

Bundled-file provenance, module naming and license locations are recorded in `assets/pdfjs/VERSION.txt`. The repository's `python scripts/verify_pdfjs.py` check verifies upstream artifact integrity and the bundled files against these documented sources.
